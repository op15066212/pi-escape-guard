# pi-escape-guard

**主要目的：调用工具前拦住写转义的人。** 已经不是「事后还原」了——那是补漏。

起因是同一件事反复发生：要写一段中文，却写成一段转义序列。
写的人（模型）为了绕开字符串字面量里的转义，越绕越深：写转义、包一层脚本、脚本里再写转义。
这个插件在**工具真的执行之前**拒掉它，并告诉他这段本该是什么。

已经落盘的转义仍然会还原（`tool_result` 与 `message_end` 两个槽位），
但那是补漏，不是主路。**主路是让它一开始就写不出来。**

## 三道口

| 位置 | 判据 | 动作 |
|---|---|---|
| `tool_call` | 入参里有 ≥ `block.min` 个**连续**转义 | 拒绝执行，`reason` 里给出它本该是什么 |
| `tool_result` | 段内 ≥ `threshold` 个转义，且不在代码上下文 | 还原 |
| `message_end` | 同上 | 还原 |

第一道是 2026-11-25 加的。使用者指出：此前三道里没有它，等于**只在事后补救**。

### 为什么门槛是「连续」而不是「总共」

正则字符类 `[\u4e00-\u9fff]` 是两个转义，但中间隔着 `-`——那是**必要写法**，
写代码绕不开。所以判据按「一段里连续几个」算，默认 3。

测试里钉着这条边界：`min=2` 时两个连续转义要拦，而正则字符类那种（不连续）仍然放行。

### 一个我自己踩进去的坑

第一版用 `JSON.stringify(event.input)` 再匹配。**stringify 会把一个反斜杠写成两个**，
于是 `\u4f60` 到了字符串里变成 `\\u4f60`，匹配不到，拦截恒不生效。

这正是这个插件要治的病：**我加的那一层把判据挡住了。**
修法不是再 `JSON.parse` 还原（那是用一个转义去解另一个），是**直接遍历原值里的字符串**，一层都不加。

## 它治的病：为什么要写这种东西

一段文本里要出现一个字面转义（比如文档里要举 `\u4f60` 这个例子），写它的人就得数反斜杠。
每多一层（字符串字面量一层、写进文件一层、文件里的正则再一层），就多一道转义。

数错了不会报错，只会**写出别的东西**。2026-11-25 我自己在这一类上连错四次：

| 我本来想做的事 | 实际发生 |
|---|---|
| 用脚本改文件 | 正则里的反斜杠穿了三层，改成了别的内容 |
| 在判据里拼一段源码再写盘 | 生成出来的探针是坏的，判据报「目标文件没导出」，而手写同样的探针跑同一条命令是好的 |

第二次最坏：**判据自己不准**。它会让人去改本来没坏的代码，比没有判据更坏。

于是写它的人只剩两条路：

1. 直写，然后人工核对每一层反斜杠对不对
2. **用代码生成代码**——写一个脚本，让脚本去写那个文件

第二条路越走越深：改文件要脚本，脚本里的反斜杠又数不清，于是再包一层。
这就是「转义层数太多」的形状，也是这个插件要拆掉的东西。

### 它拆在哪一头

它拆在**读**的那一头：记录里已经有 `\u4f60` 了，还原成「你」，模型下一轮读到的就是中文，
不会学着照抄。写那一头也就没有「必须写转义」的压力了。

### 一条我自己违反了的规矩

2026-11-25 我为了躲开 JS 字符串里的转义，改用 python 脚本去改文件。
**那正是这个插件要消除的病**——只是换了个语言继续生成代码。

正确的做法是查一件事再决定：**工具本身会不会额外加一层转义？**

实测（`tools.write` 写一行含三个字面转义的文件，`od -c` 看落盘字节）：

```
反斜杠个数=3   落盘就是 3 个，没有多一层
```

**不额外转义。所以直写就行，一层都不需要。**
这条路上一轮我绕了四次，代价是四次返工 + 一条坏掉的判据。

## 证明项精确到这一条

四条判据（C1–C4）的「引入」格都是一条只跑 `test/scan.test.ts` 的命令，
不是 `npm test`。那个文件的用例名里带 C 号，红了能一眼看出是 C1 还是 C3。

```text
node --experimental-strip-types --test test/scan.test.ts   13 条
```

判据也写成了代码：`引入` 格必须匹配 `--test test/<文件>.test.ts`，出现 `npm test` 就红。

## 上下文状态机：一次扫描，不按行猜

判断「这个转义段在不在代码里」用的是 `src/context.ts` 的 `contextMap`：
一次字符级扫描，给每个字符标出它是 `prose` / `fence` / `inline-code` / `assign` / `quote`。

**为什么不用逐行正则**：逐行判不出三件事——

```text
一 围栏跨多少行（旧实现只有一个布尔量，嵌套与未闭合都乱）
二 转义段跨行时，前半在正文、后半在围栏里
三 行内反引号开了没关，下一个反引号在哪
```

**顺带消掉了一类 bug**：旧实现在循环里维护一个累加的 `off`，把行内偏移翻译成全局偏移，
v1 三次偏移错误都从那个翻译里长出来。`contextMap` 给的是全局下标，与判据要的坐标系天然对齐，
替换也从「按行分桶」改成「全局偏移直接切」。

**`quote` 不是代码**：这条一开始写错了，把 `quote` 也算进 `isCodeSpan`，
于是带引号的正文永远还原不了（`'意思是 "..." 这三个字'`）。测试当场红。

## 查看当前门槛

```text
/escape-guard
```

四行，拿**当前配置**现场跑三种样例：

```text
threshold 3   开关 开
该还原   还原 25 字符
不够数   不动
代码里   不动
```

第三种是围栏内的正则 `/[\u4e00-\u9fff]/`——它不该被动，动了代码就坏。

**为什么不记「还原过几次」**：那个数字不改变任何动作，属于观测（R12 删过 stats）。
能自证的是「现在这条门槛遇到这三种输入会怎么做」，任何时刻可跑，不依赖历史。

### 不进 pi 也能查：`npm run status`

上一条命令是 pi 内部命令，脚本和别的 agent 调不到。CLI 给同样的四行：

```bash
cd ~/.pi/agent/extensions/pi-escape-guard && npm run status
```

`want` 不写死：从「段内转义数 ≥ 门槛」推导。所以把 `threshold` 调到 6 时，
第一条会变成 `不动`，退出码仍然是 0——**门槛是可配的，判据不该因为配置变了就自己红**。

加 `--json` 出机读：

```json
{
  "threshold": 3,
  "on": true,
  "demos": [
    { "label": "该还原", "want": true, "hit": true, "ok": true, "saved": 25 },
    { "label": "不够数", "want": false, "hit": false, "ok": true, "saved": 0 },
    { "label": "代码里", "want": false, "hit": false, "ok": true, "saved": 0 }
  ],
  "ok": true
}
```

退出码：0 三种样例都符合规则；1 有一条不符合（判据失败）。

### 四个入口，两种形状

| 从哪进 | 人读 | 机读 |
|---|---|---|
| pi 内 | `/escape-guard` | `/escape-guard json` |
| bash | `npm run status` | `node bin/status.mjs --json` |

三种样例只算一遍，两个形状从同一份结果渲染——两处各算一遍，迟早不一样。

## 元理论：依赖类型理论（唯一）

`Γ ⊢ 规则 : Prop`。一条规则就是一个类型；说它成立 = 指得出住在这个类型里的居民。没有居民就不成立，写 `sorry`，不写「显然」。

四件缺一不算规则：

| 件 | 在这份文档里是什么 | 反例 |
| --- | --- | --- |
| 形成 | 命题里每个词都能落到盘上可查的东西（`pi-escape-guard.json` 的四个键、C1–C4、`test/fixtures/` 里的坏样本） | 「必要时生效」——盘上查不到它在哪生效 |
| 引入 | 一条命令 + 它该返回的 rc | 只写「已测」，不写退出码 |
| 消去 | 换第二个入口算一遍，得同一个答案 | 两个入口读的是同一处，只算一条 |
| 反例 | 一个具体输入，喂进去这条规则就为假 | 反例格里写「视情况」 |

判法：`node verify-dtt.mjs`（rc=0）；坏样本 `node verify-dtt.mjs --selftest`（五个坏样本全红）；指纹 `node verify-dtt.mjs --fingerprint`（sha256，与 `SIGN-OFF-DTT.md` 里的一致才算签过）。

这套判法自己的反例：文档长得像规则、每格都填着形容词。`verify-dtt.mjs` 判反例格是否为空、判点名的脚本在不在盘上——形容词能过格，脚本不在盘上过不了。
## 一屏

- 装在 pi 里，自动生效，不需要命令。
- S1 工具结果、S2 助手正文：还原。S3 发给模型前：只看不动。S4 已落盘的记录：没有钩子。
- 代码里不动：围栏、行内 code、赋值行、紧邻引号的字面量、双重转义、少于 3 个转义的孤立段。
- 解的文本里混进非中文（比如 `\u0024`）也不动——那多半是正则，不是污染。

## 判据只有三条

| 判据 | 说的是 | 坏样本 |
| --- | --- | --- |
| C1 | 解出来不含字面转义 | `\u005c\u0075\u0034\u0066\u0036\u0030` 解出 `\u4f60` |
| C2 | 解出来全是 CJK（含空白、全角标点） | `\u0024\u0024\u0024` 解出 `$$$` |
| C3 | 不在代码上下文 | `const s = "…"`、``` 围栏、`名字=…` |
| C4 | 策略阈值：至少 3 个转义 | 孤立 `\u4f60` 不动 |

**C3 是四条里唯一会误伤真污染的**：它靠位置判，位置只是代理。实测代价写在 DESIGN §4。

## 性能：每个文本块都要跑，所以它有数

`tool_result` 与 `message_end` 对**每一个文本块**调一次 `settle`。
一次工具返回可能带十几块，每块几 KB 到几百 KB。单块 8ms 就是一次工具调用多 100ms。

```bash
node --experimental-strip-types bin/bench-settle.mjs
```

### 2026-11-25 改了一处：把最贵的操作推迟到确定需要时

`contextMap` 是整个 `settle` 里最贵的操作——它扫全文、给每个字符标上下文。
原顺序是**先建图再逐段筛**，于是一个字都不该改的文本也要付这笔钱。

改成两遍：先只挑「达到阈值、且不是被转义过的转义」的段；一个候选都没有就直接返回，
不建图。已有候选才建——那时这笔钱花得值。

| 场景 | 改前 | 改后 |
|---|---|---|
| 不够数，94,999 字 | 2.89 ms | 0.50 ms |
| 不够数，18,999 字 | 0.578 ms | 0.116 ms |
| 不够数，1,899 字 | 0.062 ms | 0.014 ms |
| 有污染，134,999 字 | 8.54 ms | 8.15 ms（本来就要建图）|

「不够数」这一路天天在走：真实的工具返回里零星转义很常见（日志、正则、文档片段）。

### 一个容易混的地方

`settle` 第一行是 `if (!text.includes(...)) return`，那挡的是**完全无转义**的文本
（实测 113,889 字 0.005 ms，本来就快）。这轮优化动的不是那条快路，
是「有转义但都不够阈值」那条。**两者不同，别混。**

不设阈值：耗时随机器变，卡一个绝对值会把「换台慢机」判成回归。

## 怎么验

```bash
npm run verify                  # 一条命令跑完下面全部
node scripts/gate.mjs           # 总闸：glob 发现 check-*.mjs，不靠登记
node --experimental-strip-types --test test/*.test.ts
node bin/all.mjs --selftest     # 全量扫描器自己的 6 条坏样本
```

**总闸给每条判据跑两步**：先 `--selftest`（证明它会红），再正常模式（证明现在的盘面没红）。
selftest 红了就不跑正常模式——判据本身坏了，它给的「0 处对不上」没有意义。

反例：往 scripts/ 塞一个返回 1 的 check-zzz-canary.mjs（临时造的名字，验完就删，不落盘），
gate.mjs 必须 rc=1 并点名。

### 跨仓镜像：同一份判据在两个仓里必须同答案

`scripts/check-doc-accuracy.mjs` 在本仓与 `pi-think-sentry` 各有一份，是抄的，不是共享的。

真实事故：sentry 那份 11-24 修掉了「任何表格首格都当配置键」的误报，本仓那份没跟着改，
于是同一份判据在两个仓上给出两个答案。两边各自自洽，所以两边都不会红。

`scripts/check-mirror.mjs` 钉住这一条：喂同一批 5 条样本，两个 `keysIn`/`pathsIn`
必须给出同一个答案。对端不在时 `rc=2`——跨仓判据，对端不在就说不出口径。

反例：去掉 sentry 那份的小节限制 → `rc=1`，点名「keysIn 不一致 … 本仓=[] 对端=[uniqRatio]」。
只加注释改文本 → `rc=0`，比的是行为不是文本。

## 开关

配置文件 `pi-escape-guard.json`（首次运行自动生成）。只有两个键：

| 键 | 默认 | 作用 |
| --- | --- | --- |
| `on` | true | 总开关。关掉后 `settle()` 直接返回原文本 |
| `threshold` | 3 | 一段里几个转义算「成段」。写 0 或非数字会回落成 3 |

别照着旧版填九个键——`strict` / `ratio` / `skipFixtures` / `toolResult` / `assistant` / `provider` / `report` 都不读，填了不报错也不生效。判据：`node scripts/check-doc-accuracy.mjs` → rc=0。
npm test                      # 判据、位置、记账、接线、钩子五组；条数以它的输出为准，这里不抄数
node bin/mutate.mjs           # 变异巡检：15 个变异，全部抓住，0 存活、0 锚点失效
node bin/all.mjs              # 88 个 jsonl 全量：points ≈55, ratio 1, failFiles 9
```

`failFiles 9` 不是失败，是**交还清单**：那 9 个文件里有 175 段「看着像污染但解出不是纯汉字」，
判据拒绝，需要人看一眼。它红着才说明判据没被拆。

角色检查（role）由 `verdict.ts` 的 `validMessage` 判。这一条曾经没有测试，`bin/mutate.mjs --unique` 一跑就现形——删掉 role 校验，全套测试照样绿。
role 检查守的不是还原动作，是**记账**——`note()` 在 `validMessage` 兜底之前跑，所以 user 消息也会被写进 stats 与 seen。
这就是「判等价必须构造出可区分输入」：我第一眼读代码，以为它被第二道检查完全覆盖。

## 实现里删掉的两样

- **多层 JSON 解包**：88 个文件里 12655 段 double-escaped 全是文件层的，内容层没有第二层。多层解包没有样本能验，等于未验证的代码，不写。
- 判据 `unit-mismatch`：`JSON.parse` 保证每个 `\uXXXX` 产出一个码元，这条判据恒真——恒真的判据不给信息。

两条都记在 DESIGN §10。
