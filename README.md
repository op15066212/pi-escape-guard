# pi-escape-guard

**主要目的：调用工具前拦住写转义的人。** 事后还原是补漏，不是主路。

要写一段中文却写成一段转义序列，通常不是因为不知道能直写，而是为了绕开某一层转义：
写转义、包一层脚本、脚本里再写转义，越绕越深。这个插件在工具真的执行之前拒掉它，
并告诉写的人这段本该是什么字。

已经落盘的转义仍然会还原，但那是第二道网。**第一道是让它一开始就写不出来。**

## 一个口

| 位置 | 判据 | 动作 | 反例 |
| --- | --- | --- | --- |
| `tool_call` | 入参里有 ≥ `block.min` 个**连续**转义 | 拒绝执行，`reason` 里给出它本该是什么 | 一段参数里连写三个以上 `\\u` 开头的转义 |

只有这一个钩子。2026-11-26 使用者把范围收到「只保留 tool_call 与拒绝执行」：
原来还有 `tool_result` / `message_end` 两条还原钩子，以及 `/escape-guard` 观察命令，
全部删除——事后把落盘的转义改回来是补漏，不是目的。

配置**每次调用现读**（不再靠 `session_start` 缓存）：改完文件下一次工具调用就生效。
它不报「还原过几次」——那不是判据。能自证的是「现在这条门槛，遇到这三种输入会怎么做」，
任何时刻可跑，不依赖历史。

## 为什么门槛算「连续」而不是「总共」

正则字符类 `[\u4e00-\u9fff]` 是两个转义，中间隔着 `-`，那是必要写法，写代码绕不开。
所以判据按「一段里连续几个」算，默认 3。

测试里钉着这条边界：`min=2` 时两个连续转义要拦，正则字符类那种（不连续）仍然放行。
这条边界不是调出来的，是「必要写法」与「偷懒写法」的分界。

## 判据

| # | 命题 | 门槛从哪来 | 反例 |
| --- | --- | --- | --- |
| S0 | 调用工具前，入参里有成串转义就拒 | `block.on` / `block.min`，默认开 / 3 | 一段参数里连写三个转义；而正则字符类那种两个不连续的，该放 |

**只有这一条。** 2026-11-26 使用者把范围收到「只保留 tool_call 与拒绝执行」：
原来 C1–C4 判的是「这段该不该还原」，而还原这条路径（settle 与它的位置判据、形状校验）
已整条删除。事后改回来是补漏，不是目的；目的是让它一开始就写不出来。

## 为什么不用位置判据

拦截要问的不是「这段该不该还原」，而是「你写这段参数时，本来可以直接写中文吗」。
所以这里不看位置：围栏、反引号、赋值行都不例外。唯一让步是门槛——两个不连续的转义
（正则字符类的必要写法）放行。
## 元理论

依赖类型理论是唯一判法。一条规则就是一个类型；说它成立，就要指得出住在这个类型里的居民。
四件缺一不算规则：

| 件 | 是什么 | 缺了会怎样 | 反例 |
| --- | --- | --- | --- |
| 形成 | 这个词落到盘上，对应哪个可查的东西 | 规则悬空，改代码它不跟着变 | 文档写「默认 3」，代码是 4 |
| 引入 | 一条命令加它的期望退出码 | 说成立但验不了 | 「按需检查」 |
| 消去 | 换第二个入口算一遍，得同一个答案 | 两处各算一遍，没有比较物 | 同一段在两个入口给出两个判决 |
| 反例 | 一个具体输入，喂进去这句话就假 | 只有好样本会绿，判据是恒真 | 「视情况」 |

`src/meta.ts` 的 `RULES` 是这套说法的居民：只剩 S0 一条。
「形成」格里的默认值取自 `config.ts` 的 `DEFAULTS`，不手写第二份——
改默认值时文本跟着变，于是描述与实现不会分成两件事。

## 配置

一个文件：插件目录下的 `pi-escape-guard.json`，首次启动写入默认值。
用 `ESC_GUARD_CONFIG` 指向别处。改完**下一次工具调用**就生效——配置在 `tool_call` 里现读，
不缓存、不等 `session_start`。
全部键与默认值见 `SETTINGS.md`。

## 性能

`contextMap` 是整个 `settle` 里最贵的操作：扫全文、给每个字符标上下文。
原顺序是先建图再逐段筛，于是一个字都不该改的文本也要付这笔钱。
改成两遍：先挑「达到阈值、且不是被转义过的转义」的段；一个候选都没有就直接返回，不建图。

| 场景 | 改前 | 改后 |
| --- | --- | --- |
| 不够数，94,999 字 | 2.89 ms | 0.50 ms |
| 不够数，18,999 字 | 0.578 ms | 0.116 ms |
| 不够数，1,899 字 | 0.062 ms | 0.014 ms |
| 有污染，134,999 字 | 8.54 ms | 8.15 ms（本来就要建图） |

「不够数」这一路天天在走：真实的工具返回里零星转义很常见（日志、正则、文档片段）。
另有一条更快的路：完全不含转义的文本在 `settle` 第一行就返回（实测 113,889 字 0.005 ms）。
两者不同，别混——这次优化动的不是那条。

不设阈值：耗时随机器变，卡一个绝对值会把「换台慢机」判成回归。

## 怎么验

```bash
npm run verify                  # 一条命令跑完下面全部
node scripts/gate.mjs           # 总闸：glob 发现 check-*.mjs，不靠登记
node bin/all.mjs --selftest     # 全量扫描器自己的坏样本
npm test                        # 单元测试
```

总闸给每条判据跑两步：先 `--selftest`（证明它会红），再正常模式（证明现在的盘面没红）。
selftest 红了就不跑正常模式——判据本身坏了，它给的「0 处对不上」没有意义。

反例：往 `scripts/` 塞一个返回 1 的临时判据脚本，总闸必须 rc=1 并点名它。

### 四个检查脚本

| 脚本 | 挡什么 | 反例 |
| --- | --- | --- |
| `check-doc-accuracy.mjs` | 文档里的配置键与路径，盘上必须真有 | 文档写已删的键 `strict` |
| `check-mirror.mjs` | 两个仓的 `keysIn` / `pathsIn` 行为必须一致 | 一边修掉误报、另一边没跟着改 |
| `check-rc-pipe.mjs` | 报退出码的那一行不许有管道 | `node x \| tail; echo rc=$?` |
| `check-main-guard.mjs` | 有导出的脚本，「直接跑」与「被 import」两个方向都要对 | 删掉 `isMain` 判定 |

## 它不做什么

实现里删掉的两样：观测计数（`stats` / `report`）与首见重复记账（`seen`）。
它们不改变任何一个动作——不改变动作的账本，时间一长只会变成第二个真相。

## 排错

| 症状 | 先看 |
| --- | --- |
| 该还原的没还原 | `threshold`：这段是不是不到 3 个转义 |
| 代码被改了 | C3 的洞：一行里有两个真汉字时判据会误判。把那段放进 `test/fixtures/` |
| 该拦的没拦 | `block.on` 与 `block.min`；再看入参是不是「不连续」 |

签字与未验证项见 `SIGN-OFF-DTT.md` 与 `SIGN-OFF.md`。
